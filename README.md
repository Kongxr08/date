# 时序 · 大学生个人日历

一个适合 iPhone 的可编辑日历网页 App（PWA），支持固定学期课表、国家假期停课、周课表、图片文字识别、日程导入，以及个人任务的时间规划。

## 在线使用

源码可部署到 HTTPS 静态网站服务。项目已提供 `.github/workflows/pages.yml`，GitHub Pages 配置步骤见 `DEPLOY.md`；发布是否成功以仓库 Actions 的部署结果为准。

在 iPhone 的 Safari 中打开网页，选择分享菜单 → **添加到主屏幕**。如果出现“作为网页 App 打开”，开启该选项后添加。从主屏幕图标进入可使用独立 App 界面。

Apple 操作说明：https://support.apple.com/guide/iphone/bookmark-a-website-iph42ab2f3a7/ios

## 功能

- **学期课表**：设置学期开始日期和 1–52 周长度，编辑每周固定课程，或复制日历中当前周的课程。先预览整学期，再确认生成；假期整段停课，不进行调休排课。可编辑或删除单次课程，也可修改模板后重新生成。
- **周课表**：默认显示周一至周日，纵轴为 00:00–24:00。课程块按实际起止时间排列；重叠课程并排显示，跨日课程分段显示。支持上一周 / 下一周、回到本周和日期跳转。
- **可编辑日历**：周课表与月历切换、每日安排、月历标题搜索、创建 / 修改 / 删除日程、四种分类和时间重叠提示。新建日程可连续重复 4、8 或 16 周，每条重复日程独立编辑。删除日程需要在表单内再次确认，之后可在 8 秒内点“撤销”。
- **图片识别**：从相册或系统图片选择器选择图片；Tesseract.js 在浏览器中识别简体中文与英文文字。先修改原文，再解析成可编辑草稿，逐条核对后导入。重复的标题与起止时间不会重复导入。
- **时间解析**：支持 `2026年10月12日`、`2026-10-12`、`10月12日`、`09:00–10:30`、`下午2点半–3点`，以及基于参考日期的“今天 / 明天 / 后天”。缺少年份、日期或结束时间时有核对提示。
- **个人规划**：设置任务时长、截止时间、优先级、可用时段、午休、周末规则和缓冲时间；按优先级和截止时间查找连续空闲时段，确认后加入日历。最多查找 90 天，任务不自动拆分。
- **数据保存**：日程和任务保存在当前浏览器的 localStorage。支持 JSON 备份 / 恢复和 ICS 日历导出。
- **主屏幕 App 与离线**：Web App Manifest、iPhone 图标、独立窗口、Service Worker 缓存页面。首次成功加载并缓存后可离线查看、编辑和规划。

## 重要使用边界

1. OCR 首次使用需要网络下载引擎、WebAssembly 和语言包；不承诺 OCR 完全离线。图片不上传到识别服务，但第三方 CDN 会接收下载资源的普通网络请求。
2. OCR 是文字识别加规则解析。复杂网格课表、合并单元格、“第 3–8 周”等学期周数、仅星期而无日期的安排、手写字和模糊图片，需要手动校正；并非自动理解任意课表布局。
3. 一行只生成一条日程。每行多个时间只提取第一组并提示；请拆成独立行后重新解析。没有结束时间时默认 60 分钟；结束时刻不晚于开始时刻时按次日处理，必须核对。
4. 普通日程的每周重复是独立记录。学期课程可以通过固定模板重新生成；重新生成会覆盖该学期单次课程的修改，并恢复手动删除的课次，保留其他日程。删除模板后需要重新生成，已安排课次才会移除。
5. 数据不会自动跨设备同步。Safari 和主屏幕 App 可能使用不同的数据存储，迁移时请导出再恢复 JSON。清理网站数据、卸载或更换设备前应备份。
6. 当前没有云同步、后台提醒或系统通知，也没有直接双向同步 Apple 日历；ICS 是单次导出。
7. 推荐现代 Safari（iOS 17 及以上）。项目未经过真实 iPhone 的完整兼容性验证；请按下方验收步骤在你的设备上检查安装、图片输入与文件下载。

## 学期课表使用

1. 打开“学期课表”，输入开始日期和周数（1–52），保存设置。结束日期为开始日期后 `周数 × 7 − 1` 天，包含最后一天；无需从周一开始。
2. 添加固定课程，选择星期和当天起止时间。可勾选结束于 24:00；跨午夜的课程请拆成两条。也可先从图片导入，再在日历跳转到目标周，点击“使用日历当前周”；相同名称、星期和起止时间的课程不重复复制。
3. 点击“预览整个学期排课”，核对生成课次、假期停课和替换数量。有时间冲突时需勾选接受重叠，或先修改课程。点击“确认排课并更新日历”。
4. 根据国务院年度通知，跳过整段放假日期，含假期中的周末。补班日只按原星期上课，不将工作日课表移到周末。非假期周末有固定课程时照常生成。
5. 内置 2025、2026 年已公布安排，来源分别为 [2025 年通知](https://www.gov.cn/zhengce/content/202411/content_6986382.htm)、[2026 年通知](https://www.gov.cn/zhengce/zhengceku/202511/content_7047091.htm)。联网更新使用 [NateScarlet/holiday-cn](https://github.com/NateScarlet/holiday-cn) 的年度 JSON，同步其 `papers` 公告来源，只将 `isOffDay: true` 作为假期；这不是国务院提供的官方 API。
6. 对尚未取得数据的年份会尝试联网读取，并明确提示失败；未覆盖整个学期时不生成课程。公布后点击“联网更新国家假期”再预览。更新假期不会自动改动已有日程，需要确认重新排课。
7. 当前管理一个学期模板。修改开始日期、长度或固定课程后重新生成，只替换该模板生成的日程；其他日程保留。配置及已同步假期包含在 JSON 备份中，兼容没有学期字段的旧版备份。

## 周课表使用

1. 打开“日历”中的“周课表”。横轴是周一至周日，纵轴每小时一个刻度，空白时间可按半小时选择。
2. 点某一天的空白时间，填写课程名称、开始和结束时间后保存。默认时长为一小时，可以改成任意有效时间段；也可以点“添加课程”填写。
3. 点课程块修改名称、时间、分类或备注。要删除时点“删除”，再点“确认删除”；底部出现“撤销”按钮时可以恢复。
4. 手机左右滑动查看七天，上下滑动查看一天的时间；日期表头和时间列保持固定。课程、图片导入和个人规划使用同一份日程数据。
5. 点“月历”切换到月视图。视图偏好会保存在当前浏览器，已有日程与备份格式保持兼容。

## 开发与独立部署

无需构建或安装依赖。Node.js 22 及以上：

```sh
npm start
# 打开 http://127.0.0.1:4173

npm test
```

线上只需要发布 `dist/` 文件夹，保留全部文件的相对路径。HTTPS 是 Service Worker 和稳定 PWA 使用的前提；`file://` 直接打开源码不支持完整功能。本地回环地址用于开发，不是 iPhone 可打开的线上地址。

如果部署到 GitHub Pages 子目录，资源、Manifest 和 Service Worker 都采用相对路径，可直接使用。仓库开启 Pages 的 GitHub Actions 发布方式后，随附工作流可以发布 `dist/`。

## 项目结构

```text
dist/
  index.html                 页面入口及 iPhone 元信息
  app.js                     界面、编辑、OCR、本地保存、备份及 ICS
  core.js                    学期生成、国家假期、周布局、解析、规划和数据验证
  styles.css                 桌面与手机响应布局
  manifest.webmanifest       主屏幕 App 清单
  sw.js                      页面离线缓存
  *icon*.png                 主屏幕图标
tests/
  core.test.js               核心回归测试
  week.test.js               周边界、课程位置、重叠和跨日测试
  semester.test.js           学期长度、假期停课、重新生成与数据验证
  ocr-fixture.png             中文 OCR 验证图片
server.js                    无依赖本地预览服务器
```

## 验收

1. 在周课表的空白时间新建课程，修改时间后刷新页面，确认保存；删除后撤销，检查恢复。开启重复课程后检查对应周次。
2. 图片导入选择 `tests/ocr-fixture.png`，等待真实 OCR 完成，解析为两条草稿；修改一条标题，确认后导入日历。
3. 添加有截止时间的任务，生成规划，确认其避开现有课程、午休和缓冲，再加入日历。
4. 导出 JSON，检查恢复后的日程 / 任务数量一致；将 ICS 导入支持的日历应用。
5. iPhone 添加到主屏幕，检查布局、编辑表单、相册图片输入、备份下载。联网加载一次后，在飞行模式下检查日历和编辑。

28 项自动测试涵盖学期长度、假期停课、忽略补班、重新生成、周边界、时间位置、重叠并排、跨日拆分，以及原有解析、规划和备份逻辑。浏览器 QA 结果见 `VALIDATION.md`。

## 第三方

OCR 使用 Tesseract.js 5.1.1（Apache-2.0），通过 jsDelivr 按需加载，无 API Key。引擎和语言模型由上游默认资源路径加载。项目无分析脚本。

- 源码与协议：https://github.com/naptha/tesseract.js
- API：https://github.com/naptha/tesseract.js/blob/master/docs/api.md

更新 `sw.js` 的缓存版本号后发布，可以确保修改后的页面资源在下次联网访问时更新。
